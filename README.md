# AyahSearch — Your Gateway to Quran's Wisdom
A Retrieval-Augmented Generation (RAG) chatbot that answers questions grounded in the Quran, with citations, through a simple Streamlit chat interface.

**Live app:** https://ayahsearch.streamlit.app/

---

## Overview

Ask a question in plain language, and the app:

1. Embeds your question and retrieves the most relevant Quran verses from a pre-built vector database
2. Passes those verses as grounding context to an LLM
3. Returns an answer with the source verses cited, instead of a free-floating, unsourced response

> **Note:** Hadith retrieval exists in the codebase but is currently **disabled** (commented out) — the deployed version answers using the Quran collection only. See [Roadmap](#roadmap) for re-enabling it.

## Disclaimer

This is a student/personal project, not a substitute for qualified Islamic scholarship. Answers are generated by an LLM based on retrieved verses and may be incomplete, miss context, or occasionally err. For matters of religious practice, please consult a knowledgeable scholar.

## Architecture

```
User question
     │
     ▼
Streamlit UI (app.py)
     │
     ▼
RetrievalService ──► ChromaDB (local, pre-built vector_db/)
     │                     │
     │              embeddings via sentence-transformers
     │              (all-MiniLM-L6-v2, runs locally, no API key)
     ▼
QAService ──► builds prompt with retrieved Quran verses as context
     │
     ▼
LLMService ──► Ollama Cloud API (gpt-oss:20b-cloud)
     │
     ▼
Answer + cited verses ──► back to Streamlit UI
```

**Why this split?** Embeddings are handled by a small local model (`all-MiniLM-L6-v2`, ~90MB) since embedding is cheap and fast on CPU. Generation is offloaded to **Ollama Cloud** since a 20B+ parameter model is too heavy to run on free-tier hosting — this keeps the whole app deployable on a free, cardless platform with no GPU and no dedicated server.

## Tech Stack

| Layer | Technology |
|---|---|
| UI | Streamlit |
| Vector store | ChromaDB (persisted locally, committed to the repo) |
| Embeddings | `sentence-transformers` — `all-MiniLM-L6-v2` (local, free, no API key) |
| LLM (generation) | Ollama Cloud — `gpt-oss:20b-cloud` |
| Config | `pydantic-settings` (`.env` file) |
| Hosting | Streamlit Community Cloud |

## Configuration

All configuration is environment-driven via `src/config/settings.py` and a local `.env` file (never committed — see `.gitignore`).

| Variable | Description | Example |
|---|---|---|
| `OLLAMA_API_KEY` | Your Ollama Cloud API key ([ollama.com](https://ollama.com) → Settings → API Keys) | `sk-...` |
| `LLM_MODEL` | Ollama Cloud model to use for generation | `gpt-oss:20b-cloud` |
| `CHROMA_PATH` | Path to the local vector DB | `./vector_db` |
| `QURAN_COLLECTION` | Chroma collection name for Quran verses | `quran` |
| `HADITH_COLLECTION` | Chroma collection name for hadith (unused while disabled) | `hadith` |
| `QURAN_TOP_K` | How many verses to retrieve per question | `3` |

> Only models in Ollama Cloud's hosted lineup (e.g. `gpt-oss:20b-cloud`, `gpt-oss:120b-cloud`, `deepseek-v3.1:671b-cloud`, `qwen3-coder:480b-cloud`) work with `LLM_MODEL` — small models like `llama3.2:3b` are local-only and aren't hosted on Ollama Cloud.

## Running Locally

```bash
# 1. Clone and enter the project
git clone https://github.com/saadbinfahadmahmood-tech/AyahSearch/
cd "Project - Islamic Chatbot"

# 2. Create a virtual environment and install dependencies
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt

# 3. Configure secrets
cp .env.example .env
# then edit .env and add your OLLAMA_API_KEY

# 4. Run the app
streamlit run app.py
```
The vector database (`vector_db/`) is already built and committed, so no ingestion step is needed to get started. It embeds via `sentence-transformers` locally, so this works fully offline aside from the LLM call to Ollama Cloud.

### Rebuilding the vector database (optional)

Only needed if you change the source data (`data/raw/quran.csv`) or the embedding model:
```bash
rm -rf vector_db
python -m src.ingestion.build_vector_db
```
**Important:** all consumers of the vector DB must use the same embedding model it was built with (`all-MiniLM-L6-v2`). Switching embedding models requires a full rebuild — the old and new vectors are not compatible.

## Deployment

Deployed on **Streamlit Community Cloud** (free, no billing information required):

1. Push the repo to GitHub, with `vector_db/` committed (not gitignored)
2. On [share.streamlit.io](https://share.streamlit.io), sign in with GitHub → **New app** → select this repo and `app.py`
3. Under **Advanced settings → Secrets**, set:
   ```
   OLLAMA_API_KEY = "your_key_here"
   LLM_MODEL = "gpt-oss:20b-cloud"
   ```
4. Deploy

The app sleeps after a period of inactivity on the free tier and wakes on the next visit (~10–20s cold start) — expected behavior, not a bug.

## Security Notes

- `.env` and `.streamlit/secrets.toml` are gitignored — secrets are never committed, only entered directly into Streamlit Cloud's Secrets manager
- `.streamlit/config.toml` sets `showErrorDetails = false` so visitors never see raw Python tracebacks
- Retrieval depth (`top_k`) is fixed in code rather than exposed as a public control, to keep LLM usage predictable
